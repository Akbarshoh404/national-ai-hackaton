# Deploying Raft for free

Target setup: **Render** (free Docker web service) for the API, **Neon** (free PostgreSQL) for the database, and
**Vercel** or **Cloudflare Pages** for the frontend. To run from a laptop instead, there's a **Cloudflare quick
tunnel** option.

```
 browser ──► Vercel / Cloudflare Pages (Next.js) ──► https://raft-api.onrender.com/api/v1 ──► Neon PostgreSQL
                                                         ▲
                       cron-job.org ── GET /api/v1/ping ─┘   (every 10 min, keeps the free service awake)
```

> ⚠️ **Only one copy of the backend may use a given `TG_SESSION` at a time.** Telegram treats two
> simultaneous connections with the same session from different machines as a stolen session and may revoke it
> (`AuthKeyDuplicatedError`). Then you have to run `tg-login` again. If the API runs on Render, don't also run it
> on your laptop with the same `TG_SESSION`; either give the laptop no `TG_SESSION`, or stop the Render service.
> The same goes for `TG_BOT_TOKEN`: two bots polling with one token steal each other's updates.

---

## 1. Neon (database)

1. Sign up at https://neon.tech and create a project (pick a region close to your Render region, e.g. Frankfurt
   `aws-eu-central-1`).
2. On the dashboard, under **Connection details**, copy the connection string. It looks like:
   ```
   postgresql://neondb_owner:PASSWORD@ep-xxx-123456.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```
   Use it as-is; `sslmode=require` (and `channel_binding=require`, if Neon adds it) are passed to the driver.
   Both the direct host and the `-pooler` host work. For pooler hosts the backend switches off psycopg prepared
   statements automatically.
3. The backend is built for Neon's free tier. Neon suspends compute after ~5 min idle and drops connections, so
   the pool pings before use, keeps at most 3 + 2 connections and recycles them every 5 minutes.

> Neon compute-hour budget: the background workers touch the database regularly (the extractor polls every 5 s,
> decisions rebuild every 10 min), which keeps Neon awake. Check your plan's compute allowance. To let Neon sleep
> while Telegram isn't connected, set `WORKERS_EXTRACTOR=false` and `WORKERS_DECISIONS=false` (decisions are then
> built on the first `GET /decisions` of the day).

## 2. Seed Neon from your laptop

The free Render plan has no shell, so load the demo data from your machine. Tables are created by the migrations
inside `seed --reset`.

```bash
cd backend
```
```bash
pip install -r requirements.txt
```

macOS / Linux / Git Bash:

```bash
DATABASE_URL="postgresql://…neon.tech/neondb?sslmode=require" python -m app.cli seed --reset
```

Windows PowerShell:

```powershell
$env:DATABASE_URL="postgresql://…neon.tech/neondb?sslmode=require"; python -m app.cli seed --reset
```

It prints the demo keys when done. Over the internet this takes longer than on SQLite (many small queries),
typically a few minutes. **`--reset` drops every table first**, so don't run it against a database with real data.

## 3. Render (API)

**Option A — Blueprint (recommended).** The repo contains [`render.yaml`](../render.yaml).

1. https://dashboard.render.com → **New → Blueprint** → connect the GitHub repo.
2. Render reads `render.yaml`: one **free** Docker web service built from `backend/Dockerfile`, health check
   `GET /api/v1/ping`, auto-deploy on changes under `backend/`.
3. Fill the variables marked `sync: false`:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the Neon string from step 1 |
| `CORS_ORIGINS` | your frontend origin(s), comma-separated, e.g. `https://raft.vercel.app` |
| `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` | optional — the Telegram listener stays off (with a warning) without them |
| `TG_BOT_TOKEN` | optional — the bot stays off without it |
| `GEMINI_API_KEY` | optional — rule-based fallbacks are used without it |

   `ADMIN_KEY` is generated by Render (see it under Environment).

**Option B — manual.** New → Web Service → the repo → Runtime **Docker**, Dockerfile path
`backend/Dockerfile`, Docker build context `backend`, plan **Free**, health check path `/api/v1/ping`, and the
same environment variables.

> The local model (Ollama, see README §10.12) can't run on Render's free 512 MB plan. `render.yaml` sets
> `EXTRACT_PROVIDER_ORDER=gemini,rules`. To use the local model, run the backend on a machine with Ollama (e.g.
> your laptop behind a Cloudflare tunnel, §5).

What happens on deploy:
- Render injects `PORT` (usually 10000). The image runs
  `uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}` with **one worker**.
- Alembic migrations run on startup (`AUTO_MIGRATE=true`).
- The startup log shows which workers are on, which are off and why, and the process memory (keep it under
  512 MB). pandas, openpyxl and WeasyPrint load only when a request needs them.

Check it:

```bash
curl https://raft-api.onrender.com/api/v1/ping
```
```bash
curl https://raft-api.onrender.com/api/v1/health
```

Swagger is at `https://raft-api.onrender.com/` (redirects to `/docs`).

## 4. Keep the free service awake (cron-job.org)

Free Render services spin down after ~15 minutes without traffic, and the next request waits about a minute
while the service starts again. The Telegram listener and bot also stop while it sleeps.

1. Sign up at https://cron-job.org → **Create cronjob**.
2. URL: `https://raft-api.onrender.com/api/v1/ping`, schedule **every 10 minutes**, method GET.
3. Save. `/ping` needs no auth and doesn't touch the database, so it doesn't wake Neon by itself.

Render's free plan includes a monthly allowance of instance hours. One service running 24/7 fits in it; a second
always-on free service would not.

## 5. Run from your laptop with a Cloudflare quick tunnel

No account needed; good for a demo from your own machine.

1. Start the API locally (SQLite or Neon):
   ```bash
   cd backend && .venv/Scripts/uvicorn app.main:app --port 8000
   ```
2. Install `cloudflared` (https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)
   and run:
   ```bash
   cloudflared tunnel --url http://localhost:8000
   ```
3. It prints a public URL like `https://random-words.trycloudflare.com`. Point the frontend at
   `https://random-words.trycloudflare.com/api/v1`, and add the frontend origin to `CORS_ORIGINS`.

The quick-tunnel URL changes every time you restart `cloudflared`; for a stable URL use a named tunnel with your
own domain. Remember the `TG_SESSION` warning above if Render is also running.

## 6. Frontend (Vercel or Cloudflare Pages)

- **Vercel:** import the frontend repo, framework Next.js, and set the API base URL env variable (e.g.
  `NEXT_PUBLIC_API_URL=https://raft-api.onrender.com/api/v1`).
- **Cloudflare Pages:** connect the repo with the Next.js preset (or `@cloudflare/next-on-pages`) and the same
  variable.
- Generate the typed client from the deployed spec:
  ```bash
  npx openapi-typescript https://raft-api.onrender.com/openapi.json -o src/api/schema.ts
  ```
- On the backend, `CORS_ORIGINS` must list the exact frontend origin(s), comma-separated, with no trailing
  slash, e.g. `https://raft.vercel.app,https://raft.pages.dev`. Preview deployments have their own
  origins; add the ones you use.

## 7. Telegram on the server

1. On your laptop: `python -m app.cli tg-login` → copy the printed `TG_SESSION=…` into Render's environment.
2. Resolve channels locally with `python -m app.cli tg-resolve` and commit `sources.yaml` (the server loads it on
   startup), or add sources at runtime with `POST /api/v1/admin/sources`.
3. Import history: `POST /api/v1/admin/telegram/history` with `X-Admin-Key`.

The server never uses a session file; it needs `TG_SESSION`. Without it, the startup log says
`telegram worker off: TG_SESSION not set` and everything else keeps working.

## 8. Checklist

- [ ] Neon project created; `DATABASE_URL` copied
- [ ] Seeded once from the laptop (`seed --reset`)
- [ ] Render service deployed from `render.yaml`; `/api/v1/ping` returns `{"ok": true}`
- [ ] `CORS_ORIGINS` = the real frontend origin(s)
- [ ] cron-job.org pinging `/api/v1/ping` every 10 min
- [ ] Optional secrets set: `TG_API_ID`, `TG_API_HASH`, `TG_SESSION`, `TG_BOT_TOKEN`, `GEMINI_API_KEY`
- [ ] Only one running backend uses `TG_SESSION` / `TG_BOT_TOKEN`
- [ ] In production: set `DEMO_MODE=false` once real companies use it
